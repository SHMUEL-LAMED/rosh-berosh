# ראש בראש

מערכת הצבעה למצעד מוזיקה, עם אתר ציבורי וקו טלפוני של ימות המשיח המשתמשים באותו מסד נתונים.

## תהליך ההצבעה

1. בחירת חמישה אלבומים.
2. בחירת שיר אחד מכל אלבום שנבחר.
3. בחירת זמר אחד עד שלושה.
4. אישור ושמירת הצבעה אחת לכל מזהה מצביע.

## רכיבים

- `app/` — אתר Next.js/Vinext ונתיבי API.
- `db/` ו־`drizzle/` — סכמת Cloudflare D1 והמיגרציה.
- `ivr-service/` — שירות Node.js רציף לקו ימות המשיח.

## פיתוח

```bash
npm install
npm run dev
```

אין צורך להחיל מיגרציות ביד: ה-deploy אינו מריץ אותן, ולכן בבקשה הראשונה `worker/schema-statements.js` בונה את הסכמה כולה על מסד D1 — טבלאות, עמודות חסרות, אינדקסים ושורות ברירת המחדל של `surveys` ו־`poll_settings`. כל המשפטים idempotent, כך שמסד קיים אינו משתנה ומסד ריק נבנה במלואו. הקבצים ב-`drizzle/` נשארים מקור האמת לסכמה עבור drizzle-kit. כאשר הרשימות הסופיות יתקבלו, יש להזין אלבומים לטבלת `albums`, שירים לטבלת `songs` וזמרים לטבלת `artists`.

כל משפט SQL שם רץ בנפרד דרך `prepare`, כי `D1Database.exec()` מפצל את הקלט לפי שורות ואינו יכול להריץ משפט הפרוס על כמה שורות. משפט שנכשל נרשם ללוג ואינו מונע את המשפטים שאחריו, והבקשה הבאה תנסה שוב.

שירות הטלפון דורש `SITE_API_BASE_URL` ומופעל בנפרד מתוך `ivr-service/`.

## פריסה

הוורקר נפרס משני כיוונים:

- **GitHub Action** (`.github/workflows/deploy.yml`) — על כל דחיפה ל־`main`, אחרי lint, build ובדיקות, `wrangler deploy` של `rosh-berosh`. זה מסלול הפרודקשן.
- **חיבור ה־Git של Cloudflare (Workers Builds)** — בונה ופורס כל ענף שנדחף. ב־22.9.2026 ענף שהתבסס על `main` ישן יותר נפרס דקות אחרי שהפריסה מ־`main` הסתיימה, ודרס אותה. Workers Builds גם כופה את שם הוורקר (`WRANGLER_CI_OVERRIDE_NAME`), ולכן אי אפשר להפנות ענף לוורקר אחר מתוך המאגר.

לכן `vite.config.ts` עוצר בנייה כזו לפני שהיא מגיעה לפריסה: תחת Workers Builds (המשתנה `WORKERS_CI` מוגדר) רק `main` נבנה; כל ענף אחר, וגם בנייה שהענף שלה לא ידוע, נכשל מיד עם הודעה ברורה, וב־PR מופיע X של Workers Builds. זה מכוון: הענף לא נפרס לשום מקום, ו־`main` נפרס כרגיל. מקומית וב־GitHub Action המשתנים האלה אינם מוגדרים. `tests/deploy-guard.test.mjs` שומר על הכלל.

התיקון השלם נמצא בלוח הבקרה של Cloudflare, בוורקר `rosh-berosh` → Settings → Builds: להגדיר את `main` כ־production branch ולכבות בנייה של ענפים אחרים, או להשאיר לענפים את `npx wrangler versions upload --config dist/server/wrangler.json`, שיוצר גרסת תצוגה מקדימה בלי לגעת בפרודקשן. במקרה השני מוסיפים שם למשתני הסביבה של הבנייה `WORKERS_BUILDS_ALLOW_BRANCHES=1`, וההגנה בקוד משחררת את הענפים.

## סיום השיחה בקו ההצבעה

בסוף השיחה הקו אינו מנתק אלא מעביר את המתקשר חזרה לקו הראשי `0796077075`: גם מי שההצבעה שלו נקלטה עכשיו וגם מי שכבר הצביע קודם מאותו מספר — הוא שומע את ההודעה "כבר הצבעתם במצעד ממספר זה" ומיד אחריה מועבר, במקום שהשיחה תיפול לו. אותה העברה חלה גם כשההצבעה נשמרת ומתברר בשרת שכבר קיימת הצבעה מאותו מספר. מספר היעד ניתן לשינוי ב-`POST_VOTE_TRANSFER`, והערך `off` מחזיר את הקו לסיום שיחה רגיל.

אפשר גם לצאת לקו הראשי באמצע ההצבעה: הקשה על סולמית בכל תפריט בקו ההצבעה — רשימת האלבומים, השירים, הזמרים ותפריט השלבים — משמיעה "מעבירים אתכם לקו הראשי" ומעבירה לאותו מספר. הבחירות שכבר נעשו נשמרו בכל הקשה, ולכן חיוג חוזר ממשיך מאותה נקודה.

ימות המשיח מקצה את הסולמית למקש "סיום הקשה" ואינה מעבירה אותה לקו כספרה, ולכן הקו מזהה אותה כהקשה ריקה מוסכמת. מכאן נובעת מגבלה שאי אפשר לעקוף: **מי שאינו מקיש כלום עד תום ההמתנה מועבר גם הוא**, כי הקו מקבל בדיוק את אותו ערך בשני המקרים. קודם לכן מקרה כזה השמיע "לא הוקשה בחירה" וחזר על התפריט. מאותה סיבה, בתפריט ארוך שבו הקוד הוא בן שתי ספרות, הקשה חלקית שנסגרת בסולמית (`5#` במקום `05`) נחשבת אף היא הקשה ריקה ומעבירה. תפריטי הניהול בשלוחת ההקלטות אינם מושפעים: שם הסולמית ממשיכה לסיים הקשת מספר.


## קריינות התפריטים בקו

כל תפריט הצבעה רציף מוקלט בקובץ אחד: כל האלבומים, כל הזמרים, וכל השירים של כל אלבום. ברשימה של יותר מתשעה פריטים הקו משתמש בקודים באורך קבוע, לדוגמה `01` עד `50`, כדי שהקשה על הספרה הראשונה לא תמתין ל־timeout. גם תפריטי הניהול בקו ההקלטות מושמעים כרשימה אחת ללא עמודים: אפשרויות ארוכות נבחרות בקודים כמו `01`–`15`, והקוד `00` מחזיר לתפריט הראשי.

## העלאת אלבום לאתר

תור ההעלאות שולח קובץ אחד בכל פעם ושומר את הממתינים ב-IndexedDB, כך שרענון או ניתוק אינם מאבדים אותם. הנעילה שמונעת שתי העלאות במקביל משתחררת לפני רענון הקטלוג ולא אחריו: כשהמתנה לרענון החזיקה אותה, הרינדור שהסיר את הקובץ שהסתיים בדק את התור בזמן שהנעילה עוד סגורה, ואלבום שלם נעצר אחרי השיר הראשון. העטיפה שנמצאה בתיקייה או ב-ZIP נשמרת יחד עם השירים.

## טעינת השירים ותמונות האלבום

**מהירות.** קובצי השמע והעטיפות נשמרים במטמון הקצה של Cloudflare (`serveMedia` ב-`worker/index.ts`). הבקשה הראשונה לקובץ נענית מ-R2 כרגיל והקובץ המלא נשמר ברקע, וכל בקשה אחריה — כולל בקשות Range שבהן הנגן קופץ לקטע ההשמעה — נענית מהמטמון עם 206. הכותרת `x-rosh-berosh-cache` אומרת HIT או MISS. קבצים פרטיים (הגדרות, ארכיונים, התקדמות הקו) נחסמים לפני המטמון, וקובץ גדול מ-100MB אינו נשמר בו. המטמון פועל רק בדומיין מחובר ל-Cloudflare: בכתובת `workers.dev` Cloudflare מתעלמת מ-Cache API, ולכן שם הוא כבוי והקבצים מוגשים ישר מ-R2 (כך גם מטמון הקטלוג). במקביל לקטלוג האתר מושך בבקשה אחת את קובצי כל השירים (`GET /api/catalog/media` בלי `albumIds`), שנשמרת במטמון כמו הקטלוג ונמחקת איתו בכל שינוי ניהול; כך כפתור ההשמעה כבר מוכן כשמגיעים לשירים. שיר שקובצו עוד בדרך מציג סימן טעינה ואינו פותח נגן ריק.

**תמונת האלבום היא התמונה של כל השירים שבו** — ברשימת השירים, בחלון "שמיעת השירים", בנגן ובניהול. העלאת תמונה לאלבום מחליפה את התמונה של כל שיריו, כולל עטיפות שנשלפו מקובצי השמע, ושיר שעולה לאלבום שכבר יש לו תמונה מקבל אותה בלי לשמור עטיפה נפרדת. רק לאלבום בלי תמונה העטיפה של השיר הראשון שיש בו עטיפה הופכת לתמונת האלבום.

## רשימת התפוצה

מסך התודה שאחרי ההצבעה ומסך "כבר הצבעתם" מציעים הרשמה לרשימת התפוצה. ההרשמה היא בלחיצה אחת: הכתובת נלקחת תמיד מחשבון Google המחובר ולעולם לא מגוף הבקשה, כך שאיש אינו יכול לרשום כתובת של מישהו אחר ואיש אינו צריך להקליד דבר. הלחיצה על הכפתור היא ההסכמה עצמה, אין תיבה מסומנת מראש ואין הרשמה אוטומטית בעקבות ההצבעה, ותאריך ההסכמה נשמר ב-`consented_at`. מי שכבר רשום אינו רואה את הכרטיס כלל, כדי שלא נבקש ממנו שוב.

הכתובות יושבות בטבלת `subscribers`, תמיד באותיות קטנות, עם אינדקס ייחודי שמונע כפילויות. הסרה מסמנת `unsubscribed_at` ואינה מוחקת, כדי שיישאר תיעוד להסכמה שניתנה. לשונית **רשימת תפוצה** בניהול מציגה את הרשימה, מורידה אותה לאקסל, ו**מוסיפה כתובות**: מדביקים כתובות (אחת בכל שורה, שורות מאקסל, או "שם <כתובת>") או מעלים קובץ אקסל / CSV / טקסט, בודקים בתיבה, ולוחצים "הוספה לרשימה". כתובת שכבר ברשימה לא מוכפלת, ומי שהסיר את עצמו בעבר **לא** חוזר לרשימה בייבוא (`importSubscribers`, משותף ל־`POST /api/admin/subscribers/import` ול־`POST /api/program/subscribers` של עורך המייל). האתר אינו שולח דואר בעצמו.

**טיוטת מייל על תוכנית חדשה:** אחרי פרסום של תוכנית חדשה ב"אתר התוכניות" (ובכפתור **✉ מייל למאזינים** בכל תוכנית) נפתח
עורך המייל של אתר התוכניות (`mail.html`, מחוברים דרך קוד מעבר), שיוצר מייל מעוצב כטיוטה ישירות בג'ימייל של המנהל, עם הכתובות
הפעילות בעותק מוסתר. גם כאן שום דבר לא נשלח מהשרת: הטיוטה נשלחת מג'ימייל. את הכתובות הוא קורא מ־`GET /api/program/subscribers`
(מנהלים בלבד). ההגדרה ב־Google Cloud (הפעלת Gmail API והרשאת `gmail.compose`) מתוארת ב־README של `rosh-berosh-2`.

נתיבי הניהול `POST /api/admin/subscribers` ו-`POST /api/admin/subscribers/import` נשארו בשרת בלי ממשק, לטובת הוספה ידנית וייבוא רשימות קיימות מקובץ CSV או TXT. הייבוא מזהה שורה שהיא כתובת בלבד, `שם,כתובת` בפסיק/נקודה-פסיק/טאב, ו-`שם <כתובת>`, מדלג על שורת כותרת ועל שורות בלי כתובת תקינה, ואינו משכפל כתובות קיימות.

הרישום לצינתוקים בקו הטלפון מנוהל בקו נפרד ואינו מגיע לטבלה הזו.

## שיתוף המצעד

האתר מבקש מהמצביעים להביא עוד אנשים, בארבעה מקומות (`app/share-parade.tsx`):

- **מסך התודה** שאחרי ההצבעה ומסך **"כבר הצבעתם"** מציגים כרטיס שיתוף מתחת לכרטיס ההצבעה, לפני הצעת ההרשמה לרשימת התפוצה.
- **מי שכבר הצביע** מקבל בכל כניסה מחדש חלון קופץ עם ההזמנה לשתף — פעם אחת ללשונית (`sessionStorage`), כך שרענון אינו חוזר עליה. אחרי התחברות חדשה החלון אינו קופץ, כי חלון רשימת התפוצה כבר על המסך.
- **באמצע ההצבעה** — במעבר קדימה לשלב האמצעי (בסקר של אלבומים, שירים וזמרים: הכניסה לשלב הזמרים) — החלון קופץ פעם אחת לכל דפדפן (`localStorage`); הבחירות נשמרות ואפשר להמשיך מיד. בתצוגה המקדימה של המנהל הוא קופץ בכל פעם.
- כפתור **שיתוף המצעד** קבוע בכותרת האתר פותח את אותו חלון בכל רגע.

אפשרויות השיתוף (אין כפתורי וואטסאפ וטלגרם):

- **שליחת הזמנה במייל** — בלחיצה אחת, בלי להעתיק ובלי הרשאות: נפתח מייל חדש שהנושא וההזמנה כבר כתובים בו (`inviteText` ב־`app/share-invite.js`: פתיחה, שלוש שורות על האלבומים, השירים והזמרים, והקישור בשורה משלו כדי שכל תוכנת דואר תהפוך אותו ללחיץ). במחשב נפתח חלון כתיבה של Gmail בדפדפן, עם קישור `mailto:` קטן לתוכנת דואר אחרת; בטלפון, אפליקציית המייל. בגוף המייל אין שורת כותרת (הנושא כבר אומר אותה), וכך קישור ה־`mailto:` נשאר קצר מ־2000 תווים — יש תוכנות דואר בווינדוס שקוטעות קישור ארוך יותר, ועברית מקודדת תופסת שישה תווים לאות.
- **גרסה מעוצבת** (אפשרות נוספת, "רוצים גרסה מעוצבת?"): קישור `mailto:` או חלון כתיבה של Gmail נושאים טקסט פשוט בלבד, ולכן אי אפשר למלא דרכם מייל מעוצב. הלחיצה מעתיקה ללוח את ההזמנה כ־HTML (`inviteEmailHtml`): כותרת כהה עם הלוגו, שלוש שורות וכפתור זהב "להצבעה במצעד". אחר כך הכרטיס מציג שלושה צעדים, כפתור שפותח מייל חדש עם גוף ריק, ותצוגה מקדימה של ההזמנה, והמצביע מדביק. ההעתקה סינכרונית בתוך הלחיצה (`execCommand("copy")` עם אירוע `copy` שמחליף את התוכן ב־HTML ובטקסט), כדי שלא תיכשל על הרשאות לוח או על פוקוס; `navigator.clipboard.write` הוא הגיבוי. העיצוב כולו inline, בטבלאות ובצבעים אחידים, כי תוכנות דואר מסירות `<style>`, מחלקות ומעברי צבע. הלוגו הוא `public/badge-small.png` (192 פיקסלים, כ־50KB), כי `badge.jpg` שוקל כמה מגה ונטען אצל כל נמען.
- **שיתוף ההזמנה** (כשהדפדפן תומך ב־`navigator.share`, בעיקר בטלפון): חלון השיתוף של המכשיר עם תמונת הזמנה מעוצבת (קנבס 1080×1350, באותו עיצוב כמו כרטיס ההצבעה) ועם נוסח הטקסט והקישור. התמונה נבנית מראש פעם אחת לכל טעינת עמוד, כי חלון השיתוף בטלפון חייב להיפתח מיד בלחיצה.
- **העתקת הקישור** ללוח; כשאין גישה ללוח הקישור מוצג לסימון ידני.

הקישור המשותף הוא הדומיין שממנו נפתח האתר, כך שדומיין מותאם יעבוד בלי שינוי בקוד. שום דבר לא עובר דרך השרת, ושיתוף אינו נרשם ואינו נספר. אפשרות שנשקלה ונדחתה: טיוטה **מעוצבת** שנוצרת ישירות בג'ימייל של המצביע (כמו עורך המייל של אתר התוכניות) דורשת מכל מצביע לאשר לאתר את ההרשאה `gmail.compose`. Google מסווגת אותה כהרשאה מוגבלת (restricted), וכל עוד האפליקציה לא עברה אימות אצל Google, כל מצביע רואה קודם מסך "האפליקציה לא אומתה", ו־Google מאפשרת לכל היותר 100 משתמשים חדשים. באתר התוכניות ההרשאה הזו מיועדת לכמה מנהלים בלבד.

## נתונים מתקדמים

לשונית **נתונים מתקדמים** בניהול נוספת לצד "תוצאות" ו"מצביעים" ואינה משנה אותם. היא נטענת מ-`GET /api/admin/analytics` ומוצגת דרך תפריט פנימי: נושא אחד על המסך בכל רגע, בלי עמוד ארוך לגלול בו. מה שאינו נבחר אינו מרונדר כלל.

הנושאים: **סקירה וקצב** (הפתק שמייצג את הקהל, הקצב מול התקופה הקודמת באותו אורך, הקו המצטבר והעמודות היומיות), **מתי מצביעים** (מפת יום בשבוע על שעה בשעון ישראל, ושעת הזהב לפרסום הבא), **מרוץ הדירוג**, **אלבומים ושירים** (מפת חום על הקטלוג, השיר המוביל בכל אלבום, נשירה בין שלבים, ומי בלי אף קול), **הצלבות**, **פערים וריכוזיות** (מקום בכל ערוץ, כמה חסר כדי לעלות מקום, מדד ריכוזיות, ג'יני והטיית מיקום), **חמישיות**, **זמן ההצבעה**, **קבוצות טעם**, **מי מצביע** (חוזרים, השוואה לסקר הקודם באותה נקודת זמן, מי לא סיים ומה כבר בחר, ורשימת התפוצה) ו**תפעול ותוכן**.

מעל התפריט מופיעים שני סרגלים כשיש מה לומר: **מאז שהיית כאן**, שמשווה את הדירוג לתמונה שנשמרה בדפדפן של המנהל בביקור הקודם, ו**התראת חריגה**, שמסמנת פריט שחלקו ביממה האחרונה גדול פי שניים או יותר מחלקו לאורך הסקר.

**גרפים.** אין ספריית גרפים: לפרויקט ארבע תלויות ריצה והוא נארז לוורקר, ולכן כל גרף הוא SVG שנכתב ביד, בגודל שנמדד מהמכל כדי שטקסט לא יימתח. הפלטה נבדקה ולא נבחרה בעין — זוג הצבעים של הערוצים ורמפת מפת החום עומדים ברצפות הניגודיות ועיוורון הצבעים מול רקע לבן, ולכן הזהב בגרפים כהה מזהב המותג שבכותרות. שום גרף אינו נשען על צבע בלבד: לכל אחד מקרא, תווית או טבלה מקבילה. ציר הזמן רץ מימין לשמאל, וה-SVG מוגדר `direction: ltr` כדי שעיגון הטקסט לא יתהפך תחת כיוון המסמך.

**"אחוזים בלבד"** נועד לצילום מסך. כל ספירה במסך עוברת דרך פורמטר אחד שמקבל את המצב, כך שאי אפשר לשכוח מקום אחד. **מסך שידור** פותח תצוגה גדולה למקרן שמתרעננת לבד, ו**תמונה לשיתוף** מציירת את עשרת המובילים על קנבס — ציור מחדש ולא צילום מסך, ועם `ctx.direction` מפורש, כי הקנבס אינו יורש את כיוון המסמך. **הורדת Excel** מייצאת את כל הטבלאות לגיליונות נפרדים בקובץ אחד.

**ביצועים.** השאילתות רצות בשלוש אצוות: אצווה היא עסקה אחת, ולכן טבלאות שנוצרות בעצלתיים (יומן הקו, הקריינויות) יושבות באצווה נפרדת שנתפסת — מסד חדש מציג מסך מלא שבו רק החלק הזה ריק. סטטיסטיקת הזמנים מחושבת על עד 5000 הפתקים האחרונים והמסך אומר זאת. מטמון של חמש־עשרה שניות בתוך האיזולייט מונע ממסך השידור להריץ הכול בכל רענון, ו-`?fresh=1` מדלג עליו.

**זמן ההצבעה** נמדד באתר ובקו כאחד. שני הערוצים שומרים בהתקדמות `timing`: תחילת ההצבעה, סיום כל שלב בפעם הראשונה, ומספר הביקורים או השיחות עד האישור. באתר ביקור הוא כניסה חדשה ולא רענון, לפי סימון שחי בלשונית בלבד. הפתק נשלח עם האובייקט הזה ועם שעון הלקוח, והשרת מזיז את החותמות להפרש שבין השעונים — בלי זה דפדפן שמפגר בחצי שעה היה נראה כמו הצבעה שנמשכה חצי שעה. כל חותמת נבדקת מול תחילת ההצבעה בלבד, כי בקו אפשר לסיים שלבים בכל סדר, וערך פסול הופך ל-`NULL` ואינו מפיל הצבעה. משך שלב מחושב רק כששתי נקודות הקצה קיימות, לפי השלבים הפעילים בסקר, ולעולם אינו נופל אחורה לשלב אחר. העמודות `started_at`, `albums_done_at`, `songs_done_at`, `artists_done_at` ו-`sessions` נוספות ל-`ballots`, משוחזרות משחזור ארכיון, ונמחקות באיפוס יחד עם טיוטות האתר.

**ספירת שירים.** פתק יכול היה לרשום את אותו שיר תחת כמה מהאלבומים שבחר: האינדקס הייחודי של `song_votes` כולל את מזהה האלבום, ולכן כל שורה כזו נחשבה חוקית ושיר אחד קיבל עד פי חמישה. שליחה כזו נדחית עכשיו, והספירה בשני המסכים היא לפי פתקים ומוגבלת לאלבום של השיר עצמו, כך שגם שורות ישנות אינן מנפחות דבר.

## סדר האלבומים, השירים והזמרים

לכל אלבום, שיר וזמר יש עמודת `position`, וממנה נגזר הסדר באתר ובקו. חיצי ההזזה בניהול שולחים את הרשימה כולה ל-`POST /api/admin/reorder`, והשרת כותב מחדש את כל המיקומים בקבוצה; לשירים הוא מוודא קודם שכל המזהים שייכים לאותו אלבום בסקר הפעיל.

שינוי סדר מותר רק כשההצבעה סגורה — באתר ובקו כאחד — ולכן בקשה בזמן שההצבעה פתוחה מוחזרת עם `409` וההודעה "כדי לשנות סדר יש לסגור קודם את ההצבעה". ההודעה מוצגת כמות שהיא במסך הניהול, כדי שברור מה חוסם ולא ייראה כאילו ההזזה פשוט לא עבדה.

## ניהול טלפוני

השלוחה `/recordings` היא קו ניהול מלא למספרים מורשים. הכניסה מבוססת על זיהוי המספר, וכל פעולת ניהול והעלאת הקלטה נבדקות שוב מול הרשימה המאושרת באתר ונרשמות ביומן `ivr_admin_audit`.

לכל פריט בתפריט יש שני נוסחים: `label` הוא השם הכתוב באתר ובטבלה שלמטה, ו-`spoken` הוא מה שהקו מקריא — "להוספת אלבום הקישו 5 1". כל קוד נאמר ספרה ספרה בסוף המשפט, ולעולם לא בתוך הטקסט (בתוך משפט ימות המשיח הייתה קוראת "תשעים ותשע" במקום "תשע תשע"). ימות המשיח גם מוחקת נקודות מטקסט להקראה, ולכן כל משפט נשלח כהודעה נפרדת ולא כמחרוזת אחת עם נקודות — אחרת הכול נשמע רצף אחד בלי הפסקות. שם הנושא אינו נאמר פעמיים בכניסה אליו, וההסבר על הקשת קוד ישיר נאמר רק בתחילת השיחה.

בתפריט הראשי כל נושא נבחר בספרה אחת: `1` לקריינויות, `5` לתוכן וכן הלאה. הקוד המלא בן שתי הספרות (`10`, `50`) ממשיך לעבוד מכל מקום. גם ברשימות הארוכות של הניהול מקישים מספר טבעי — `1` ולא `01`. אחרי הספרה הראשונה הקו ממתין רגע קצר (`IVR_MENU_SEC_WAIT`, ברירת מחדל 5 שניות) כדי לראות אם באה ספרה שנייה, והקשה על סולמית מסיימת מיד. בקו ההצבעה נשאר אורך קבוע (`01`–`50`), כי הקריינויות המוקלטות של התפריטים אומרות את הקודים המרופדים.

לכל פעולה יש קוד קבוע בן שתי ספרות, ואפשר להקיש אותו מכל תפריט בקו בלי לחפש בשלוחות: קוד שמסתיים ב-0 פותח נושא, `00` חוזר לתפריט הראשי, `99` מסיים את השיחה, ו-`91` משמיע את המפה כולה. אחרי כל פעולה הקו חוזר לרשימת הנושא שממנה הגיעה, כדי לבצע כמה פעולות ברצף.

הוספת פריט בקו יוצרת אותו מושבת עם שם זמני, ומיד אחריה הקו מציע להקליט את שמו ולהפעיל אותו; את השם הכתוב אפשר לעדכן באתר. במערכות שבהן מוגדר שירות קריינות אוטומטית, `15` ו-`16` מייצרים קריינות מהשם השמור בלי הקלטה. אי אפשר להסיר בשיחה את המספר שממנו מנהלים, את המספר המורשה האחרון או את מנהל האתר האחרון. פעולות שמחייבות קובץ או טקסט חופשי — העלאת שירים ותמונות, שינוי שמות כתובים והוספת כתובת מנהל אתר — נשארות באתר.

## אתר התוכניות

**כניסה אחת.** מתחברים פעם אחת — באתר הסקר או באתר התוכניות — ומחוברים בשניהם. אתר התוכניות
בודק ברקע (`GET /api/program/sso`, ניווט רגעי שמחזיר קוד חד־פעמי או `sso=none`) אם כבר מחוברים כאן,
ואחרי כניסה באתר התוכניות הדפדפן עובר לרגע דרך `/api/program/handoff/<קוד>?return=…`, שקובע את
עוגיית אתר הסקר. רק כתובות של אתר התוכניות מותרות כיעד חזרה. התנתקות מנתקת משניהם.

**דף ניהול אחד.** אתר התוכניות מנוהל כחלק רגיל של `/admin`, באותו עיצוב ובאותה כניסה: בתפריט הצד
יש חלק **"אתר התוכניות"** (תוכניות, הודעה ועדכונים, מאזינים, פרסום התוכניות) לצד כל חלקי הסקר
(`app/admin/programs-admin.tsx`). העבודה נשמרת אוטומטית בטיוטה בשרת (`/api/program/draft`), ו"פרסום
התוכניות" מעביר אותה לאתר. הלשונית הפתוחה נשמרת בכתובת (`/admin#prog-site` וכו'), והכתובת
`admin.html` של אתר התוכניות מעבירה לכאן.


אתר התוכניות של ראש בראש (המאגר `rosh-berosh-2`, ב־GitHub Pages) שומר את התוכניות באותו D1 ואת ההקלטות באותו R2, דרך הנתיבים `/api/program/*` של הוורקר הזה. **אין לו רשימת מנהלים משלו: מי שמנהל כאן מנהל גם שם.** הרשימה היא אותה רשימה — `ADMIN_EMAILS` ועוד מה שנוסף בלשונית **הרשאות** — ונבדקת מחדש בכל בקשה, כך שהוספה או הסרה של מנהל כאן חלה מיד גם על אתר התוכניות.

הכניסה לאתר התוכניות נפתחת בחלון קטן בכתובת הוורקר, `/api/program/login`. **כל אחד** יכול להתחבר שם עם Google ולקבל סשן לאתר התוכניות (אזור אישי); מי שכבר מחובר לאתר הסקר מקבל את הסשן מיד (`POST /api/program/auth/session`, שמחליף את עוגיית הסשן של אתר הסקר בטוקן ל־30 יום ורץ רק מאותו origin). `user.isAdmin` — שמחושב מחדש מרשימת המנהלים בכל בקשה (`GET /api/program/me`) — הוא מה שפותח שם את אזור הניהול ואת הכתיבה (`POST /api/program/catalog`, `/api/program/upload`).

ההקלטות של התוכניות שמורות בקובצי Google Drive משותפים. גוגל מגיש אותם כאודיו עם Range לשרתים, אבל עונה 403 לכל בקשת דפדפן חוצת־אתרים (`Sec-Fetch-Site: cross-site`), ולכן הנגן של אתר התוכניות מזרים אותם דרך הוורקר: `GET/HEAD /api/program/stream/<מזהה קובץ>` מעביר את כותרת ה־Range לדרייב ומחזיר את האודיו (200/206) עם `content-range`; דפי HTML של גוגל (חסימה, אזהרת וירוסים) לעולם אינם מועברים — במקומם מוחזר 502. רק מזהים של הקלטות שמופיעות בתוכנית בקטלוג מוזרמים; כל מזהה אחר מקבל 404.

### נתיבים נוספים של אתר התוכניות

- **תוכניות מתוזמנות.** תוכנית עם `publishAt` (שעון ישראל, `"2026-10-01T20:00"`) אינה מופיעה בקטלוג הציבורי, בהורדה ובדף השיתוף עד שהמועד מגיע; מנהלים רואים הכול.
- **הגנה מהתנגשות בפרסום.** `GET /api/program/catalog` מחזיר למנהלים `versionId` (הגרסה האחרונה). `POST /api/program/catalog` מקבל `baseVersion` — אם מאז פרסם מישהו אחר מוחזר 409 עם `conflict: true` ו־`latest` (אלא אם נשלח `force: true`) — ומחזיר את `versionId` החדש. `notify: true` מכניס לתור התראת דחיפה על תוכניות שהפכו עכשיו לציבוריות (עד 3, ומעבר לזה התראה מסכמת אחת). שתי תוכניות עם אותה כתובת (`slug`) — 409 עם `כתובת כפולה: <slug>`; מותר להעביר כתובת מתוכנית שנמחקה או להחליף כתובות בין שתי תוכניות באותו פרסום.
- **העלאה בחלקים** (עד 1GB להקלטה, 15MB לעטיפה — אותם גבולות גם ב־`POST /api/program/upload` הרגיל): `POST /api/program/upload/start?episode=&kind=` → `PUT /api/program/upload/part?key=&uploadId=&part=` (חלקים של 20MB) → `POST /api/program/upload/complete` (או `/abort`). הקובץ מוגש מ־`/media/<key>` עם Range.
- **הורדה עם שם הקובץ:** `GET/HEAD /api/program/download/<מזהה>` — מ־R2 עם `content-disposition` בשם התוכנית בעברית; אם ההקלטה עוד רק בדרייב — הפניה (302) להורדה מדרייב. **כל הורדה נספרת** (אירוע `download` ב־`program_events`): פעם אחת לכל מכשיר, לכל תוכנית, בכל יום. לא נספרים HEAD, בקשת המשך (Range שלא מתחיל בבית 0), בוטים וסורקי קישורים של תיבות דואר, בקשה בלי דפדפן, והורדה של תוכנית מוסתרת. `?ref=email` (הקישור במייל של רשימת התפוצה) — ההורדה נספרת כ"מהמייל"; בלי `ref` המקור נקבע לפי הדף שממנו לחצו (אתר התוכניות, דואר, ישיר).
- **דף שיתוף:** `GET /p/<slug>` — תגי Open Graph לוואטסאפ ופייסבוק והפניה מיידית לדף התוכנית (`?t=<שניות>` נשמר).
- **נתונים אישיים:** `GET/PUT/DELETE /api/program/userdata` (לכל חשבון מחובר, עד 300KB; הלקוח ממזג). **לייקים:** `GET/POST /api/program/likes`.
- **התראות דחיפה (Web Push):** `GET /api/program/push/key`, `POST /api/program/push/subscribe`, `POST /api/program/push/unsubscribe`, ולמנהלים `POST /api/program/push/send`, `POST /api/program/push/drain` ו־`GET /api/program/push/count`. מפתחות VAPID נוצרים בשימוש הראשון ונשמרים ב־`program_settings`. **השליחה נעשית במנות:** בתוכנית החינמית של Workers מותרות 50 בקשות יוצאות להפעלה, ולכן כל הודעה נכנסת לתור (`program_settings` → `push-pending`, עד 20 הודעות) ואף הפעלה אינה שולחת יותר מ־25. כל מנה "נתפסת" בכתיבה מותנית של התור לפני השליחה, כך ששני ריקונים במקביל (דף הניהול וה־cron) לעולם אינם שולחים את אותה מנה פעמיים. `send` שולח מנה ראשונה מיד; פרסום עם `notify` רק מכניס לתור; ובשני המקרים לקוח הניהול קורא ל־`drain` בלולאה עד ש־`remaining` מגיע ל־0. טריגר cron (כל 5 דקות, `triggers` ב־`vite.config.ts`) שולח בכל ריצה מנה מהתור, ומכניס לתור התראה על תוכנית מתוזמנת כשמועד הפרסום שלה מגיע; בריצה הראשונה הוא רק רושם את התוכניות הקיימות, כך שתוכניות ישנות לעולם אינן מפעילות התראה. פרסום עם `notify: false` רושם גם את התוכניות המתוזמנות או המוסתרות שבו כ"כבר הודיעו", כך שה־cron לא ישלח עליהן התראה כשמועדן יגיע. מנוי מתקבל רק מכתובת של שירות דחיפה של דפדפן (FCM, Apple, Windows, Mozilla, Samsung), ולכל חשבון נשמרים עד 10 מכשירים.
- **סטטיסטיקות:** אירועי ההאזנה (`POST /api/program/events`) — `play` (התחילו לנגן), `listen` (שניות האזנה, עד 600 באירוע, עם `pct`) ו־`complete` (הנגן שמע 90% מהתוכנית בניגון רציף) — מקבלים גם `pct` ו־`ref`. **"האזנה"** היא מאזין אחד (אותו מכשיר, באותו יום) בתוכנית אחת שנספרת רק אם שמע לפחות את הסף (ברירת מחדל 10 דקות) או את כל התוכנית; **"האזנה מלאה"** — שהגיע ממנו `complete`. כל המספרים נספרים מיום ההתחלה (`since`, תאריך בישראל; ברירת מחדל `2026-09-24`). `/api/program/stats` מחזיר `config` (`{ since, minSeconds }`), ולכל שורה (`days`, `episodes`, `recent`, `totals`) את `plays` (האזנות), `listeners`, `seconds`, `full` (האזנות מלאות), `starts` (כל מי שהתחיל) ו־`downloads`; `week` ו־`month` — גם הורדות; `downloads.sources` — מאיפה הורידו; וגם `sources`, `hours`, `likes`. `GET /api/program/stats/episode/<מזהה>` מחזיר את אותם מספרים לתוכנית ועקומת נטישה (`retention`, של כל מי שהתחיל). **הגדרת הספירה (מנהלים):** `POST /api/program/stats/config` עם `{ minMinutes }` (1–60), `{ since: "YYYY-MM-DD" }` (לא בעתיד) או `{ reset: true }` (מהיום) — נשמרת ב־`program_settings` (`stats`). האירועים הישנים לא נמחקים: תאריך מוקדם יותר מחזיר אותם.
- **תמלול אוטומטי:** בפרסום הקלטה חדשה ל־R2 היא נכנסת לתור. משימה מתוזמנת ממשיכה חלק אחד (2MB) בכל דקה, שומרת התקדמות ב־D1 ומנסה שוב אחרי תקלה. יש מגבלה של 60 חלקים ביום לתמלול האוטומטי, כדי להגביל שימוש ב־Workers AI. בפריסה הראשונה התוכנית האחרונה שכבר קיימת נכנסת גם היא לתור; ארכיון שלם אינו נשלח בבת אחת. `GET /api/program/ai/transcript/<מזהה>` מציג למנהלים התקדמות ושגיאה. `POST /api/program/ai/transcribe` נשאר כגיבוי ידני, ו־`POST /api/program/ai/summarize` יוצר תיאור מהתמלול. התמלולים אינם חלק מהקטלוג הציבורי.
- **הגהה בבינה מלאכותית (מנהלים):** `POST /api/program/ai/proofread` עם `{ items: [{ key, text }] }` (1–40 פריטים, עד 40,000 תווים). המודל מתקן רק כתיב, גרשיים (`''` ← `״`), רווח אחרי פיסוק והתאמה — בלי ניסוח מחדש ובלי לגעת בשמות ובאימוג׳ים. מוחזרים רק פריטים שהשתנו: `{ results: [{ key, fixed, changes: [{ from, to }] }] }` (עד 30 שינויים ברמת המילה לכל פריט); תשובה שאי אפשר לקרוא — 502.
- **הצעות לשם מהתמלול (מנהלים):** `POST /api/program/ai/titles` עם `{ episodeId }` — דורש תמלול שהושלם (אחרת 409); Claude כשמוגדר `ANTHROPIC_API_KEY`, אחרת Workers AI. מחזיר `{ titles: string[], whatsapp: string }` — עד 5 שמות קצרים (2–6 מילים, בלי מירכאות ומספר תוכנית, בלי כפילויות) והודעת וואטסאפ של 2–3 שורות בלי קישורים; תשובה שאי אפשר לקרוא או תקלה — 502.
- **פרטי הקשר:** `settings.contacts` מתפרסם עם הקטלוג (כמו `banner` ו־`updates`) — `{ phone, phone2, email, phoneNote, hostsNote, chatNote }`; עד שנשמר לראשונה מוחזרים הערכים שהיו קבועים באתר. שדה שלא נשלח נשאר בברירת המחדל, ו־`""` מרוקן אותו.
- **תגובות המאזינים (באישור מנהל):** `POST /api/program/comments` (`{ episodeId, text, at? }`, מחוברים בלבד, 2–1000 תווים, `at` — שנייה בתוכנית) נשמרת כממתינה. `GET /api/program/comments?episode=<מזהה>` מחזיר `comments` (מאושרות, נעוצות קודם ואז מהישנה לחדשה, עם שם פרטי בלבד) ו־`mine` (הממתינות של המשתמש המחובר). למנהלים: `GET /api/program/comments/all?status=pending|approved|hidden|all` (עם `pending` — מספר הממתינות), `POST /api/program/comments/moderate` (`{ id, status?, pinned?, reply? }`) ו־`DELETE /api/program/comments` (`{ id }`).
- **"הרגעים הכי חמים":** `POST /api/program/moments` (`{ episodeId, at, on }`, מחוברים בלבד, 30 בדקה) מסמן או מבטל ♥ על רגע בתוכנית ציבורית — `at` מעוגל למטה לכפולה של 5 שניות, עד 200 רגעים לכל מאזין בכל תוכנית — ומחזיר `{ ok, at, on }`. `GET /api/program/moments/mine?episode=<מזהה>` מחזיר רק את הסימונים של המשתמש המחובר (`{ moments: [at…] }`). הסיכום — למנהלים בלבד: `GET /api/program/moments/<מזהה>` מחזיר `{ id, total, buckets: [{ at, count }], top }` (חלונות של 30 שניות, מאזינים שונים, `top` — 5 החלונות העמוסים), ו־`/api/program/stats` מחזיר גם `moments` — 10 התוכניות עם הכי הרבה סימונים ב־90 הימים האחרונים.

**שלושה צעדים ידניים לבעלי החשבון:**
1. **Workers AI חייב להיות מופעל בחשבון Cloudflare** (הקישור `AI` מוגדר ב־`vite.config.ts`); בלעדיו התמלול והסיכום מחזירים שגיאה, ושאר האתר עובד כרגיל.
2. **אופציונלי — סיכומים טובים יותר בעברית:** `npx wrangler secret put ANTHROPIC_API_KEY`. כשהמפתח מוגדר הסיכום נעשה ב־Claude (`claude-sonnet-5`), ואחרת ב־Llama של Workers AI.
3. **ניקוי העלאות שלא הושלמו:** העלאה בחלקים שנקטעה (דפדפן שנסגר באמצע) משאירה ב־R2 חלקים שתופסים מקום. את זה אי אפשר להגדיר מהקוד: ב־R2 → bucket → Settings → Object lifecycle rules: מחיקת העלאות לא גמורות אחרי יום.
