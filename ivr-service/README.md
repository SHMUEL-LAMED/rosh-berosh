# rosh-berosh-ivr

שירות טלפוני עצמאי שמחבר את מערכת הסקרים "ראש בראש" לקו הטלפוני של ימות המשיח.

## למה זה שירות נפרד מהאתר?

ימות המשיח קוראים לכתובת שלך בכל הקשה של המתקשר ("webhook"), ואתה עונה להם מה
לעשות הלאה. הספרייה שאנחנו משתמשים בה (`yemot-router2`) שומרת את מצב השיחה
בזיכרון של תהליך Node.js אחד שרץ ברצף, כדי לאפשר לכתוב את כל תסריט השיחה כפונקציה
רגילה עם `await`. זה לא תואם לאתר שרץ על Cloudflare Workers (כמו האתר הראשי),
ששם כל בקשה מטופלת בנפרד בלי זיכרון. לכן השירות הזה חייב לרוץ במקום שמאפשר
תהליך Node.js קבוע - שרת VPS, Render, Railway, Fly.io וכו' (לא Vercel/Cloudflare
בפריסה הרגילה שלהם, כי גם שם כל בקשה נפרדת).

## התקנה

```bash
npm install
cp .env.example .env
# ערכו את .env - צריך להזין את כתובת אתר הסקרים שלכם
npm start
```

## פריסה ועדכון

חשוב להבין: השירות הזה **אינו נפרס יחד עם האתר**. ה-workflow שב-
`.github/workflows/deploy.yml` מריץ `wrangler deploy` ומעלה רק את ה-Cloudflare
Worker. כל שינוי בתיקייה הזו נשאר לא פעיל בקו עד שמעדכנים בנפרד את השרת שמריץ
אותו. אחרי כל מיזוג שנוגע ב-`ivr-service/` צריך לעדכן גם את השרת.

### עדכון שרת קיים (VPS, או כל מקום שמריצים בו את התהליך ידנית)

```bash
cd /path/to/rosh-berosh
git pull
cd ivr-service
npm ci --omit=dev
# והפעלה מחדש של התהליך - לדוגמה:
#   systemctl restart rosh-berosh-ivr
#   pm2 restart rosh-berosh-ivr
```

### עדכון בשירות מנוהל (Render / Railway / Fly.io וכדומה)

ברוב השירותים האלה יש חיבור ל-GitHub שמפעיל פריסה אוטומטית בכל דחיפה ל-`main`.
אם החיבור קיים, מספיק למזג ל-`main` והשירות יתעדכן לבד. אם לא, יש ללחוץ
`Manual Deploy` / `Redeploy` בממשק של הספק. חשוב שהגדרת ה-Root Directory של
השירות תהיה `ivr-service`, כי הריפו מכיל גם את האתר.

### פריסה עם Docker

בתיקייה יש `Dockerfile` מוכן. הקשר הבנייה (build context) הוא התיקייה הזו:

```bash
cd ivr-service
docker build -t rosh-berosh-ivr .
docker run -p 3000:3000 \
  -e SITE_API_BASE_URL=https://rosh-berosh.example.com \
  -e IVR_SECRET=... \
  rosh-berosh-ivr
```

### בדיקה שהעדכון תפס

לשירות יש נתיב בריאות שלא דורש שום פרמטר:

```bash
curl https://ivr.example.com/healthz   # אמור להחזיר: ok
```

כדי לוודא שהקוד עצמו התעדכן ולא רק שהתהליך חי, אפשר לדמות שיחה עם `curl`
לפי הדוגמאות שבסוף הקובץ הזה, ולבדוק שהתשובה מכילה את ההתנהגות החדשה.

## משתני סביבה

- `SITE_API_BASE_URL` - כתובת הבסיס של אתר הסקרים "ראש בראש" (בלי סלאש בסוף),
  לדוגמה `https://rosh-berosh.example.com`. השירות קורא משם את
  `GET /api/catalog` ושולח את ההצבעה אל `POST /api/ballots` עם
  `channel: "phone"`.
- `IVR_SECRET` - סוד משותף שנשלח בכותרת `x-ivr-secret` בכל פנייה לאתר, וזהה
  לערך של `IVR_SECRET` המוגדר ב-Cloudflare Worker. בלעדיו האתר דוחה הצבעות
  טלפוניות, והשירות עוצר מיד בהפעלה. **חובה.**
- `RECORDINGS_YEMOT_TOKEN` - טוקן ניהול סודי של מערכת ההקלטות
  `0772267078`, המשמש רק להורדת ההקלטה המאושרת והעברתה לאתר ולקו ההצבעה.
- `RECORDINGS_FOLDER` - השלוחה במערכת `0772267078` שבה יישמרו ההקלטות,
  לדוגמה `/99`.
- `RECORDINGS_YEMOT_API_BASE` - כתובת API חלופית למערכת ההקלטות. אם לא
  הוגדרה, נעשה שימוש ב-`https://www.call2all.co.il/ym/api`.
- `POST_VOTE_TRANSFER` - מספר היעד שאליו מועברים המתקשרים בסיום ההצבעה.
  אם לא הוגדר, נשמר מספר ברירת המחדל הקיים.
- `PORT` - פורט מקומי (ברוב שירותי האחסון מוגדר אוטומטית).

כדי שקובצי הקריינות שמועלים באתר יועברו אוטומטית גם למערכת הטלפונית, יש להוסיף
ב־Cloudflare Worker סוד בשם `YEMOT_TOKEN`. הערך הוא טוקן הניהול של ימות המשיח.
אפשר להגדיר גם `YEMOT_API_BASE` אם המערכת נמצאת בשרת אחר; ברירת המחדל היא
`https://www.call2all.co.il/ym/api`.

אפשר להגדיר ב־Cloudflare גם `ADMIN_EMAILS` כרשימת כתובות מנהלים המופרדות
בפסיקים. מנהלים שמתווספים דרך האתר נשמרים בנפרד ואינם דורשים שינוי קוד.

## הגדרה בממשק הניהול של ימות המשיח

1. בכנסו לממשק הניהול של ימות המשיח ובחרו שלוחה (למשל השלוחה הראשית `/`).
2. הגדירו את סוג השלוחה כ-`api` (מודול API - תקשור עם מחשבים חיצוניים).
3. הגדירו `api_link` לכתובת שהשירות הזה רץ עליה, לדוגמה:
   `https://ivr.example.com/`
4. חשוב: אין להגדיר `api_hangup_send=no` (עבור ביצועי זיכרון תקינים בספרייה).

### קו נפרד להקלטת קריינויות

1. במערכת `0772267078` צרו שלוחת API, לדוגמה `/99`, והגדירו את
   `api_link` לכתובת שירות Render עם הסיומת `/recordings`.
2. הגדירו ב-Render את `RECORDINGS_YEMOT_TOKEN` ואת
   `RECORDINGS_FOLDER=/99`. את הטוקן שומרים רק כערך סודי ואין להכניסו לקוד.
3. באתר, במסך "קריינות לקו", הוסיפו את מספרי הטלפון שמורשים להקליט. אין קוד
   כניסה; הזיהוי מתבצע אוטומטית לפי מספר המתקשר.
4. המתקשר בוחר הודעת מערכת, תפריט אלבומים, שירים לפי אלבום או זמרים.
   רשימות עם יותר מתשע אפשרויות מחולקות לעמודים של שמונה פריטים, והספרה 9
   עוברת לעמוד הבא. אפשר להקליט כל עמוד רציף, או אלבום, שיר וזמר בודדים. לאחר
   ההקלטה שומעים את תפריט האישור הרגיל של ימות המשיח ומאשרים.
5. ההקלטה המאושרת יורדת אוטומטית מהמערכת `0772267078`, נשמרת באתר עם נגן,
   מועברת למערכת ההצבעה ונרשמת כקריינות הפעילה.

## איך זה עובד

1. מתקשר מתקשר לקו וימות המשיח קוראים לשירות הזה.
2. השירות משמיע תפריט ראשי קצר: לבחירת אלבומים מקישים 1, לבחירת שירים מתוך
   האלבומים שכבר נבחרו מקישים 2, ולבחירת זמרים מקישים 3.
3. בסיום כל חלק חוזרים לתפריט הראשי, בלי לאבד את הבחירות שכבר נעשו.
4. אחרי שכל החלקים הפעילים הושלמו, השירות שולח את ההצבעה לאתר
   (`voterKey` = מספר הטלפון של המתקשר, כדי
   למנוע הצבעה כפולה מאותו טלפון - בדיוק כמו שהאתר מונע הצבעה כפולה מאותו
   דפדפן).
5. כל הודעה ושם פריט ניתנים להחלפה בהקלטה אנושית דרך מסך "קריינות לקו"
   באתר. כשאין קובץ פעיל, המערכת משתמשת בהקראה אוטומטית.
6. משמיעים הודעת תודה ומנתקים.

## הערה חשובה על טקסט מוקרא

ימות המשיח דוחים (וזורקים שגיאה על) כל טקסט שיש בו את התווים: נקודה, מקף,
גרש, גרשיים, או `&`. כברירת מחדל בקוד הזה (`removeInvalidChars: true`) התווים
האלו פשוט **מוסרים אוטומטית** מהטקסט לפני השליחה, כדי שזה לא יקרוס. שימו לב
לכך אם תוסיפו הודעות טקסט חדשות.

## בדיקה מקומית בלי טלפון אמיתי

אפשר לדמות בקשות מימות המשיח עם `curl`, לדוגמה:

```bash
curl "http://localhost:3000/?ApiCallId=test1&ApiPhone=0500000000&ApiDID=0771234567&ApiExtension=1"
```

לתגובה הראשונה (תפריט) יהיה `val_1=1` בהקשה הבאה כדי לדמות הקשה על "1":

```bash
curl "http://localhost:3000/?ApiCallId=test1&ApiPhone=0500000000&ApiDID=0771234567&ApiExtension=1&val_1=1"
```
